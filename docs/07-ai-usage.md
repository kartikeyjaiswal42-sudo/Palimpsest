# How AI tools were used

The brief asks for this at the end and says it is not scored. Answering honestly.

## What was used

**Claude (Opus) via Claude Code**, as the primary development environment, for essentially
all of it: writing the Python and JavaScript, designing the feature set, running the
experiments, and drafting this documentation. Sessions were interactive — proposing an
approach, running it, reading the numbers, and changing course when the numbers disagreed.

**Four Claude sub-agents**, once, to search for and verify public essay corpora. They were
given a hard rule — report the real HTTP status and never claim a URL you did not fetch —
and their findings were spot-checked by hand before anything was used. That search is what
turned up the Liang et al. corpus, which became the backbone of the project.

**Claude also wrote the first machine-essay corpus**, and that turned out to be the most
instructive mistake in the project. Eleven essays composed to read like model output. They
were nearly undetectable, and the diagnostic showed the strongest feature was measuring the
prompt's own instruction to "vary sentence length" rather than machine authorship. Prose
*composed* to sound machine-generated does not carry the signature of prose *sampled* from a
model. They are now a held-out adversarial set on which the detector scores 0 of 11. Full
account in [04-failures.md](04-failures.md#4).

## What was not used

- **No AI in the scoring path.** GPT-2 is read for token probabilities; nothing is ever asked
  for a judgement. This is the central design constraint and there is a test that enforces it.
- **No AI-generated numbers.** Every figure in the README and in `docs/` is copied from the
  output of `scripts/train.py`, `scripts/evaluate.py` or `scripts/find_failures.py`. Where a
  number appears in prose it can be regenerated by running that script.

## How the work was checked

The honest answer is that the checking was done by running things, and that several claims
died in the process:

- A 0.988 AUROC was suspected of being an artifact, so we measured the character
  distributions and found human essays were 88% smart-quoted and machine essays 0%.
- A document AUROC of 1.000 was interrogated rather than reported, which surfaced the
  document-length leak and the 41% ESL false-positive rate it was causing.
- The claim that self-relative features reduce ESL bias was not asserted; it was measured
  against a matched ELL control and a graded proficiency gradient, and the result reframed
  the whole ESL analysis.

Where something is unverified it is labelled unverified. The Hamilton College corpus is
absent because a bot-challenge blocked it, not because we forgot; that is written down in
[02-dataset.md](02-dataset.md).

## Judgement about the tooling

Using a language model to build a language-model detector has one specific hazard, and we hit
it head-on: the model is a fluent and confident generator of *plausible* machine-style text,
and it is very easy to accept that text as data. What caught it was insisting on a diagnostic
that could embarrass the approach — per-feature AUROC split by generation condition — rather
than one that would confirm it.
